# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Язык

- Общение с пользователем — на русском.
- Все описания — на русском: сообщения коммитов, описания PR, документация, комментарии в коде, тексты интерфейса.

## Проект

«Первые 100 слов» — PWA для Android: мама записывает первые 100 слов малыша. Согласованные требования и список отложенных функций — в `requirements.md` (это главный источник правил поведения приложения). Обсуждение, из которого они выросли, — в `pervye_100_slov_dialog.md`.

## Команды

Сборки, зависимостей, тестов и линтера нет — обычные HTML/CSS/JS, раздаются как статические файлы.

- Запуск локально: из папки `docs/` выполнить `python -m http.server 8765 --bind 127.0.0.1` и открыть http://localhost:8765 (именно `localhost`: только он разрешён для входа в Google). Service worker, микрофон и установка на главный экран работают только на `localhost` или по HTTPS, не через `file://`.
- Публикация: push в `main`. Workflow `.github/workflows/ci.yml` прогоняет проверки (`node --check`, `.github/check.py`) и публикует `docs/` на GitHub Pages через Actions: https://dimarsoft.github.io/first-100-words/. Локально проверки: `python .github/check.py <базовый-коммит>`.
- Версия ПО — последний git-тег `vX.Y.Z`; `docs/git-info.json` (версия, коммит, дата) собирает CI, в репозитории лежит заглушка `0.0.0-dev`, её не править. Новая версия: `git tag vX.Y.Z` и `git push --atomic origin main vX.Y.Z` (тег должен прийти вместе с коммитом, иначе сборка возьмёт старую версию).
- После любого изменения в `docs/` увеличить `CACHE` в `docs/sw.js` (`first100-v1` → `v2` …) и добавить новые файлы в список `FILES`, иначе установленное приложение не обновится. CI это проверяет и падает.
- Обновление установленного приложения: `sw.js` берёт файлы с сервера в обход HTTP-кэша (`cache: 'no-cache'`, при установке `'reload'`), сеть в приоритете, кэш — для офлайна. `setupUpdates()` в `app.js` проверяет обновление при возврате в приложение и перезагружает страницу на `controllerchange`, но не в форме слова, не во время записи и не во время обмена с Диском (`driveBusy`) — тогда после перехода на другой экран.

## Архитектура

Всё работает в браузере, своего сервера нет; данные покидают телефон только по команде пользователя — файлом резервной копии/экспорта или копией в его Google Диск.

- `docs/app.js` — всё приложение, по разделам: обёртка IndexedDB → состояние → даты → слова и ударение → маршрутизация по хэшу → по функции отрисовки на каждый экран (список, форма, карточка, статистика, настройки, первый запуск) → резервная копия (`makeBackupBlob()` / `applyBackup()` — общие для файла и Диска) и экспорт → Google Диск → `init()`.
- Google Диск: Google Identity Services (токен ~1 час, только в памяти), scope `drive.file` — приложение видит лишь свой файл `Первые 100 слов — копия.json` (формат резервной копии, перезаписывается, загрузка resumable из-за размера с аудио). `GOOGLE_CLIENT_ID` в `app.js` — публичный ID OAuth-клиента; пустая строка скрывает кнопки Диска. Origins клиента: `https://dimarsoft.github.io`, `http://localhost:8765` (локально — `localhost`, не `127.0.0.1`). Service worker не перехватывает запросы к чужим доменам. Обещания пользователю — в `docs/privacy.html` (русский + английский для проверки Google), открытая страница «О приложении» — `docs/about.html` (это Home page в OAuth Branding; название там — «Первые 100 слов» и «First100Words»): при изменении работы с данными обновлять обе. Владение доменом `dimarsoft.github.io` подтверждено в Google Search Console файлом `googledfe5fa267d760525.html` в отдельном репозитории `dimarsoft/dimarsoft.github.io` (корень домена; там же переадресация на `about.html`) — файл и репозиторий не удалять, иначе подтверждение слетит.
- `docs/index.html` содержит все экраны как `<section id="view-…">`; `showView()` переключает `hidden`. Маршруты через `location.hash` (`#/`, `#/new`, `#/edit/<id>`, `#/word/<id>`, `#/stats`, `#/settings`) — чтобы работала кнопка «Назад» на Android. После сохранения использовать `location.replace`, чтобы «Назад» не возвращал в форму.
- `docs/words.js` — `window.COMMON_MEANINGS`, начальные подсказки для поля «Что значит» (объединяются с уже введёнными значениями).
- Хранилище: IndexedDB `first100`, хранилища `words` (keyPath `id`) и `meta` (ключи `child`, `celebrated`, `lastBackupAt`, `lastChangeAt`, `driveLinked`, `driveSavedAt`). Аудио хранится как `Blob` внутри записи слова (и внутри элементов `history[]`). Новые поля добавлять только через миграцию: увеличить `DB_VERSION` и добавить ветку `if (e.oldVersion < N)` в `onupgradeneeded`; у каждой записи есть поле `schema`.
- Запись слова: `pron` (строчными, как набрано), `stress` (индекс ударной гласной или null), `meaning`, `date` (`YYYY-MM-DD`, местное время), `self`, `story` («Как появилось слово?» — единственное поле-комментарий), `audio`/`audioType`, `draft`, `history[]`, `createdAt`/`updatedAt`.

## Правила предметной области, которые легко нарушить

- Единица учёта — пара «произношение → значение»: одинаковый `pron` с разными значениями — разные слова. То же значение с новым `pron` — предложение обновить существующее слово (старое произношение и аудио уходят в `history`), а не новое слово.
- Ударение показывается заглавной ударной гласной (`display()`); это фактическое ударение ребёнка, а не нормативное. Одна гласная — ударение ставится само; две и больше — сохранить нельзя, пока не нажата гласная. Набранная заглавной гласная принимается как выбор ударения.
- Даты: по умолчанию сегодня; нельзя в будущем и раньше дня рождения; при редактировании дата не сбрасывается.
- Черновики («Дополнить позже») требуют только `pron` и не входят в счёт 100, нумерацию, статистику и рубежи.
- Рубежи 10/30/50/80/100 поздравляются по одному разу (`meta.celebrated`).
- Даты в списке короткие (`12 нояб`, год — только если не текущий); возраст ребёнка в списке — только у первого слова, а в карточке — у каждого.
- Аудиозапись ограничена 60 секундами (`MAX_AUDIO_SEC`), Opus 32 кбит/с (`AUDIO_BPS`, минута ≈ 0,23 МБ; по умолчанию Chrome пишет 128 кбит/с). Максимум (200 слов × 1 мин) — ~46 МБ данных, копия ~62 МБ (аудио в base64).
- Прогресс передачи на Диск — через XMLHttpRequest (у fetch нет прогресса отправки), показывается для копий от `PROGRESS_MIN_BYTES` (1 МБ).
- «Поделиться» (`shareOrDownload`): тип файла передавать без параметров (`audio/webm`, не `audio/webm;codecs=opus`), без Web Share — скачивание.

## Правила репозитория

- Коммиты — обычный `git commit`, автор из локального git-конфига репозитория; никаких строк `Co-Authored-By` и другой атрибуции Claude.
- Репозиторий публичный: не коммитить резервные копии и экспорт (`slova-kopiya-*.json`, `slovar-*.csv` в `.gitignore`), не добавлять имя ребёнка и личные данные в код и документацию.
